# Architecture — claimr

Index and **controlled vocabulary** for claimr's architecture. The names listed
here are canonical: any `components:` / `aspects:` field in a claimr document
must use them verbatim, and skills validate against this file.

Individual component and aspect docs live under [`components/`](components/)
and [`aspects/`](aspects/) and are written on demand — a name can exist in the
vocabulary before its doc does. Schemas live in aivolution-meta
(`docs/schemas/architecture-component.md`, `docs/schemas/architecture-aspect.md`).

## Components

Nameable building blocks — a crate, module, or binary you can point at.

| Name      | What it is |
|-----------|------------|
| `parser`  | `src/parser/` — LR parser generated by rustemo from `claimr.rustemo` at build time (`build.rs`), with semantic actions (`claimr_actions.rs`) that build the AST in `src/ast.rs` (numeric literals become the exact rational `Number` type in `src/number.rs`); public entry points `parse_program` / `parse_clause` in `src/lib.rs`, errors as `ParseError` with line/column. Decision: [`../design/2026-08-17-rustemo-parser-generator-over-nom.md`](../design/2026-08-17-rustemo-parser-generator-over-nom.md). |
| `cli`     | `src/main.rs` — the `claimr` binary: parses a file and prints its clauses. |
| `grammar` | `src/parser/claimr.rustemo` — the formal grammar of the language, from which the parser is generated. `docs/reference/grammar.md` is a rendered EBNF view of it. |

Future components (evaluator, constraint solver, REPL) are added here when
they exist.

## Aspects

Cross-component invariants — rules that survive replacing any single component.

| Name                | Invariant (summary) |
|---------------------|---------------------|
| `grammar-authority` | `src/parser/claimr.rustemo` is the single source of truth for the language's syntax — the parser is generated from it, so it cannot drift; `docs/reference/grammar.md` and the README are views that follow it, never the other way round. Every construct in the grammar has at least one parsed example under `examples/`. |
| `exact-arithmetic`  | Numbers are exact arbitrary-precision rationals (integers = denominator 1); no floating point anywhere in the language core; decimal literals denote exact rationals; irrational reals exist only semantically as values of under-constrained variables. Decision: [`../design/2026-08-17-exact-rational-arithmetic.md`](../design/2026-08-17-exact-rational-arithmetic.md). |

## Litmus test

If you can name the crate/module/binary that implements it, it's a
**component**; if it's a rule that survives replacing any single component,
it's an **aspect**.
