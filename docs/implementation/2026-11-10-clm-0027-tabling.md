# CLM-0027: Tabling for recursive rules

## Premise

The accepted record `2026-11-10-tabling-for-recursive-rules.md`: a
directive `:- table name/arity.` declares a tabled predicate; its table
belongs to the program, is keyed by the call's variant, is computed over
the world store alone and holds ground answers as a set in insertion
order; a call consumes its table by unification in the caller's store;
completion is by linear tabling; a sub-search over a table under
evaluation is an error; each answer records its first derivation.

## Shape of the implementation

**Grammar.** `Clause` gains `Directive: ':-' name=Ident
indicators=Indicator+[Comma] '.'`, `Indicator: name=Name '/' arity=Number`.
A rule's `:-` follows an atom, a directive's begins the clause: no LR
conflict (checked with `rcomp --force --dot`). AST
`Clause::Directive { name, indicators: Vec<(String, Number)> }`, printed
`:- table ancestor/2.`; the arity is validated at compile time (a
non-negative integer; an unknown directive name, a built-in or `'<>'` are
positioned compile errors, `EvalError::BadDirective { message, span }`).

**Program.** `tabled: HashSet<PredKey>`; `world: Store` — the initial
store built once at compile (it was already built there to validate the
constraint facts) and cloned per evaluation (`Store` gains `Clone`);
`tables: RefCell<Tables>` — the registry, since `solve` takes `&self` and
the machine holds `&Program`. `TTerm` gains `PartialEq, Eq, Hash` so a
variant key and a ground answer are plain `TTerm`s.

**Machine, one store at a time.** The machine keeps one `store` field; an
evaluation *swaps* it: the caller's store is parked in an evaluation
frame (`eval_stack: Vec<EvalFrame>`), a clone of the world takes its
place, and the frame's finishing choice point swaps it back. Every goal
and choice point of the evaluation sits above that choice point and is
gone before the swap back, so no address crosses stores. The evaluation
is the goal list `[Resolve(abstract call), TableOne]` with an empty tail:
`Goal::Resolve` resolves an already-built call (the key instantiated with
fresh variables); `Goal::TableOne` finalizes the store, snapshots the
call (`Store::snapshot`; `None` → `EvalError::NonGroundTabledAnswer`),
records the answer if new — with its derivation rendered from the arena
records made since the evaluation started, when explaining — and fails,
so the search moves on; the list never empties. `Retry::TableFinish`
(the evaluation's choice point, below everything of the evaluation) is
reached when the clauses are exhausted: it pops the frame, decides
completion (below), swaps the store back and consumes the table for the
original caller. `Retry::Answers { key, next }` is the consumption choice
point: build answer `next` on the heap, unify with the call, push the
choice point for the following answers; the answer count is read at
retry time, so a consumer of a table under evaluation also sees answers
added after it started.

**Completion (linear tabling).** A table is `Complete`, `Evaluating(d)`
(frame `d` of the stack) or `Incomplete` (returned while depending on a
lower frame). Call to a `Complete` table: consume. To an `Evaluating(d)`
one: every frame above `d` gets `leader_min = min(leader_min, d)`, frame
`d` is marked `looping`, and the caller consumes. To an `Incomplete` or
absent one: evaluate. At `TableFinish` of frame `f` at depth `d`: if
`looping && leader_min == d` and any table grew during the pass
(`Tables.total` against the count at the pass's start), re-run — push the
frame and the choice point again, same goals, pass count reset;
otherwise, if `leader_min < d` the table becomes `Incomplete` and is
appended, with `f`'s own dependents, to frame `leader_min`'s dependents;
else the table and its dependents become `Complete`. Each pass either
adds an answer or ends; an `Incomplete` table called again in a later
pass is re-evaluated, so the leader's iteration carries its dependents.
A query that stops inside an evaluation (error, interrupt) removes every
non-complete table from the registry and swaps the outermost store back,
so the next query starts clean.

**Sub-searches.** When a call consumes a table that is not `Complete`,
the current goal list is scanned for a `Commit` or `CollectOne`: one
present means the call is inside a condition or a comprehension body of
the same evaluation (the evaluation's list has an empty tail, so nothing
outside it is seen), and the query stops with
`EvalError::IncompleteTable { predicate, construct }`.

**Explanations.** `ProofKind::Tabled { call, key, idx }` on consumption;
`Resolution::Tabled` (`"tabled"`); the node's subgoals are the stored
derivation, cloned. The answer-tree rendering is factored to render the
arena from an index, with the records below it as roots, so `TableOne`
renders an evaluation's slice with the evaluation's store. Inside an
evaluation the query's variable names are not used (they address the
parked store).

**REPL and CLI.** The REPL recompiles the session per query, so tables
live for a query there and for the file in batch mode; a directive at
the prompt extends the session like any clause and `:list` prints it.
`highlight.rs` needs no change (`:-`, `/`, identifiers and numbers are
existing terminals).

## Action items

1. Grammar, AST, actions, printer; `rcomp` check.
2. Compile: directive validation, `tabled`, `world`, `tables`; `TTerm`
   derives; `Store: Clone`.
3. Machine: `Goal::Resolve`, `Goal::TableOne`, `Retry::TableFinish`,
   `Retry::Answers`, the evaluation stack and the completion rules, the
   store swap, variant keys (`Store::variant_key`), consumption,
   sub-search detection, cleanup on abort, `names()` for rendering.
4. Errors: `BadDirective`, `NonGroundTabledAnswer`, `IncompleteTable`,
   `CyclicTabledCall`.
5. Explanations: `Tabled` resolution, factored rendering, JSON value.
6. Example `examples/tabling.claimr` + `.answers`: a cyclic part-of graph,
   left and right recursion with the same answers, a count, negation over
   a complete table, a constrained caller, mutual recursion.
7. Tests: left/right recursion on a cycle (same answers, once each);
   variant key with constrained and bound arguments; the store-independence
   case (`old(bob)` against a caller's `{ age(bob) < 60 }`, on
   backtracking); mutual recursion; non-ground answer error; negation and
   comprehension over complete tables, and inside the recursive group (the
   error); directive errors; parse round trip; `tabled` explanation node
   whose cited clauses reproduce the answer; JSON vocabulary; a long chain
   (right recursion, 2 000 nodes) on a small stack; interruption inside an
   evaluation; REPL directive at the prompt.
8. Docs: `grammar.md`, `README.md`, `evaluator.md`, `answer-soundness.md`
   (invariant 5 restated, invariant 8: a table is a function of the
   program), `json-output.md`, architecture README (`cli` row), this plan.
